# Dynamic template sharing previews

## One design, current catalogue data

`shared/template-share-card.mjs` owns the single HTML/CSS design used for all website and video template share cards. There are no per-template graphics to maintain. The artwork, title, short description, FMI number, current price, original price and offer label come from the same public catalogue APIs used by the storefront.

`server/template-share.mjs` resolves only currently public templates. It hashes their display fields, artwork reference/published version, shared HTML design and deployment revision to produce a new image URL when those inputs change. New templates work automatically when they appear in the public catalogue. No database migrations or production writes are required.

`server/template-share-image.mjs` renders that HTML into a 1200×630 JPEG only when a sharing client needs an image. It uses the existing Montserrat fonts, transparent logo and actual catalogue thumbnail. Browser rendering disables scripts and external requests, and uses embedded, validated assets. Generated bytes are cached briefly in memory, not committed as individual assets. Catalogue data is cached for 30 seconds, response/CDN caching is 60 seconds and rendered images expire from the warm cache after five minutes. Versioned artwork URLs or published template versions should be used when replacing artwork, as elsewhere in the catalogue.

The samples under ignored `work/glass/` are verification artifacts, not inputs to the application.

## Routing and sharing

- `/templates?product=...&kind=...` receives server-rendered Open Graph metadata for every visitor, including crawlers without JavaScript. This specific rewrite precedes the old generic brand crawler rule. The application shell remains in the page.
- `/template-share-images/:kind/:product/:revision.jpg` serves the current card image. Only public catalogue identifiers are accepted; arbitrary image URLs, customer drafts, private exports and credentials are not accepted.
- New copied links carry the stable `share=card-v1` marker to distinguish them from old generic links. The canonical Open Graph URL remains the clean product URL. Old product URLs also receive the corrected metadata.
- `og:video` exposes the existing public MP4 demo where available. Receiving apps decide whether to use it; it does not guarantee playback inside WhatsApp or Instagram.
- The sharing dialog displays the generated card and provides Copy link, WhatsApp, Instagram and Save preview image. Instagram uses native file sharing when the device supports it, with copy-link and image-download fallbacks. No messages are sent automatically.
- Paid/personalized guest invitation sharing remains on its existing separate route and publication checks.

## Platform findings, checked 17 November 2026

[WhatsApp's official link-preview guidance](https://developers.facebook.com/documentation/business-messaging/whatsapp/link-previews/) requires populated Open Graph tags in the HTML head, within the first 300 KB of the page. Preview images should be at least 300px wide, below 600 KB and no wider than a 4:1 aspect ratio. WhatsApp explicitly treats previews as best effort. Our generated examples are well below the image limit.

[Instagram Sharing to Stories](https://developers.facebook.com/documentation/instagram-platform/sharing-to-stories/) documents native Android intents and iOS URL/pasteboard integrations requiring a Facebook App ID. It is not a general website link-posting endpoint. [The browser Web Share API](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/share) can hand files to device-provided targets, subject to browser support and user activation. Users can also save the card and attach it manually with the template link.

[Open Graph](https://ogp.me/) defines the image and optional video metadata used here. A JPEG is the transport representation of the shared HTML design, not a manually maintained source of product data.

The site cannot replace preview cards in messages already sent or force another app to clear its own cache. Catalogue/price updates appear on newly fetched previews after the short server cache expires; existing messages may retain their earlier appearance.

## Verification

- `tests/server-template-sharing.mjs`: public-only lookups, escaped metadata, changed-field revisions, one shared HTML design, JPEG dimensions/size, GET/HEAD/error responses, crawler/browser equivalence and rewrite order.
- `tests/browser-template-sharing.mjs`: Wisteria Walk, Wedding Bells and a website template; initial server HTML; 320/390/1440px share-dialog bounds; copy and WhatsApp targets; native JPEG share handoff; image download and unsupported-device fallback. Native sharing is mocked, so this does not claim physical WhatsApp or Instagram delivery.
- Existing share and preview/audio regression checks preserve paid invitation privacy and video preview behavior.

Changes remain local until the user authorizes deployment.
